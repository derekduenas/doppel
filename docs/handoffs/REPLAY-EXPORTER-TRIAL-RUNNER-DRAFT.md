# Draft · Canonical replay exporter and trial runner

For Opus review. Implementation is pending the applicable freeze lift. This spec targets the admission contract on `746cf42`. Run replay on research compute with sealed tape and test it in CI.

## 1. Interface and evidence

Proposed command:

```sh
doppel promote replay-export --run-spec "$RUN_SPEC" --plan "$PLAN" \
  --plan-sha256 "$PLAN_SHA" --data "$SEALED_TAPE" --lab "$FROZEN_LAB" \
  --registry-root "$REGISTRY_ROOT" --commit-sha "$RELEASE_SHA" --out "$RUN"
```

Require an independently pinned `plan.json`, a verified registry, immutable closed tape and hourly receipts, the token map when needed, and an operator-pinned clean release. The preregistered run spec ties those inputs to frozen subject IDs, variant definitions, split dates, window policy, cost/depth execution rules, and locked seeds. Its digest and the supplied plan digest belong in the run receipt. The plan's `frozen_ns` and the registration must precede the forward replay period. Pin the admission release's evaluator hash and validate it before and after replay.

Use `doppel.shadow-replay-run-spec/v1` with `run_id`, `plan_sha256`, `commit_sha`, `scoring_sha256`, `simulation_sha256`, `family`, `forward_range_s` (half-open), `window_policy_sha256`, `scenario_policy_sha256`, and an ordered `attempts` array keyed by `trial_id`. Each entry pins the variant definition and any genome or fixed abstention definition by digest. Resolve evidence references relative to the run spec. Verify each loaded artifact against its receipt, and match attempt IDs one-for-one against the plan. Downstream record `input_sha256` from the bound evaluation, which verifies the actual snapshot after it closes.

Output `trials.json` for the full family, `candidates/<trial_id>/replay.json` for each candidate with a canonical eligible series and binding PASS, and `run-receipt.json` for review. Keep raw fill traces, input checksums, and partial-depth and exclusion diagnostics in the research output. Record their hashes in the replay or run receipt as applicable. Emit canonical JSON with sorted keys for signed inputs. Stage files, fsync, and publish without replacing completed output. Running again on identical sealed inputs must reproduce the canonical artifacts byte-for-byte. Wall clocks and operational logs belong outside those bytes.

The exporter prepares unsigned bytes. The existing `doppel promote bundle` is the signing step. Its detached Ed25519 signature authenticates the manifest's exact SHA-256 of `replay.json`, the plan, the ledger, the evidence and the release. Use the operator-approved key and the existing signature domain. The exporter needs no private key. A signed canonical replay is a replay file together with its verified approval manifest and signature.

## 2. Binding replay and depth scenarios

1. Use `Registry.verify()`, `Registry.registration()`, `Registry.protocol_binding()` and the existing sealed evaluator's `replay_snapshot()`. Locate the first binding result. Verify its full verdict against `verdict(..., **VERDICT_OPTIONS)` and the evaluation metadata returned by that replay. Require the exact genome ID, replay interval, input and evaluator hashes, protocol, and simulation digest. For diagnostic or failing trials, retain the measured series and disposition for the trial ledger. Publish a candidate replay only for a binding `PASS`.
2. Emit `doppel.shadow-replay/v1`: `genome_id`, explicit `trial_id`, full `commit_sha`, the exact registry `verdict`, `windows`, and `scenarios`. Copy window start/end, eligibility, and the evaluator's exact per-window `net_c` (net cents over the whole window). Preserve exclusion reasons and include measured no-trade eligible windows as zero. The candidate series must reproduce the registry bootstrap p-value and match its ledger row exactly. Require at least 32 eligible, nonoverlapping windows on the shared grid.
3. Replay nine independent scenario cells at sizes `25`, `100`, and `500`. Use the same sealed policy, window universe, receipt clock, inventory and risk rules. Each cell requests its target size at every eligible entry or passive quote opportunity. Count a quote when the policy calls for a new order or replacement, once per order and side. Exit size comes from scenario inventory. Count entry or quote opportunities before applying the size cap or available liquidity, including zero and partial completions. Count an opportunity as `filled` only when it completes the full target in the order's permitted life. Carry partial executions into P&L, label depth shortfalls, and report separate partial, no-fill, risk-cap, limit and unavailable-book counts. Unobservable windows follow the locked window policy.

| Canonical `fee_tier` | `coefficient` | Fee treatment |
|---|---:|---|
| `api_live_rebated` | 0.02085 | PM US API taker fee at 0.0695 with the 70% rebate applied after venue rounding. Record the scenario's promo validity and fee assumptions. |
| `api_base_0695` | 0.0695 | PM US API taker fee without the rebate. |
| `maker_0` | 0.000 | Zero-fee comparison. For an aggressive strategy this cell is diagnostic for its economics. |

Reuse the existing per-fill PM US rounding and rebate helper (`lab.markout.tier_fee_usd`). Keep passive fills at zero standard maker fee and account for aggressive exits at the scenario's taker tier. Keep a `gateway_0095` comparison in the research report when the v3 protocol requires it. The live-fee gate uses `api_live_rebated`.

The current twin IOC execution consumes only the best level. Implement an additive scenario replay path with access to full retained L2 as of simulated landing. For buys walk asks from lowest up, for sells walk bids from highest down. Honor price limits, freshness, risk and close time at each executable level. Decrement consumed depth in each scenario so later attempts cannot reuse it without observed replenishment. Compute VWAP as `Σ(px × filled_qty) / Σ(filled_qty)` and apply fees to actual fills. Passive entries require pessimistic L2 FIFO queue and fill accounting, including cancel latency. Walk L2 for aggressive exits and retain a separate sweep-capacity measurement for passive quote opportunities without treating a sweep as a maker fill. Record both sources in the diagnostic receipts. Keep the registry verdict path byte-identical for the bound evaluator.

Each cell emits `fee_tier`, `coefficient`, `size`, `execution=l2_book_walk_vwap`, `attempted`, `filled` and `net_c` (total cents across the cell's window panel). Require `attempted > 0` and `0 <= filled <= attempted`. Emit per-window net, HAC, mean net and contract completion statistics in the research report. An unavailable cell blocks the signed export. Measured insufficient depth remains in a cell's denominator. Admission requires at least one profitable live-rebated cell with full-target completion of at least 50% of attempts.

## 3. Complete trial ledger

- Preregister an ordered inventory of all wallets and variants to be evaluated, including controls, before evaluation. Each plan row contains four 64-character hex values: `trial_id`, `genome_id`, `subject_id`, `variant_id`. Define stable subject and variant hashes over normalized wallet identity and immutable variant specification. Derive trial IDs from those IDs, candidate identity and a preregistered run ID. For a variant that can abstain before it emits a genome, reserve a deterministic non-candidate ID in its plan row and record that it has no executable genome. Only the exact registered executable genome ID can be selected for admission. If identity depends on a development fit, seal that fit and reconcile the predeclared search inventory before any forward data is read.
- Journal every evaluated variant across the declared family, including abstentions, fitted failures, errors and all variants screened on an outcome. Count the nine reporting cells under one trial when the grid and selection rule were locked in advance. A cell whose result influences a newly chosen policy or parameter requires its own recorded trial. Keep development and forward evidence labelled. A variant count based on the shortlist is incomplete. An unplanned evaluation leaves the current plan ineligible for admission; preserve the discrepancy and use a new preregistered forward interval for any amended plan.
- Checkpoint each attempt's start and sealed outcome by `trial_id`. One writer closes rows in plan order, including rows from parallel workers. The canonical ledger uses zero-based `seq`, the exact plan identity, `previous_sha256` (64 zeros at genesis), and `sha256` of the sorted-key row minus `sha256`. Include disposition, reason, data/fit/source hashes and `returns_c` where observed in the hashed row. Retries use the same ID and immutable inputs, with execution diagnostics retained. A changed variant is a separate trial. On resume verify the plan, tape and prior bytes, and reject any divergent result or skipped sequence. Use a single durable append log for the work in progress and materialize its exact ordered row chain as `trials.json` at closure.
- The final `doppel.shadow-trial-ledger/v1` carries `plan_sha256`, exact ordered `windows` as `[start,end]` pairs, and `trials`. Require one terminal row per plan entry, exact registry family coverage, unique IDs and identity tuples, one shared eligible return grid, and equality to the candidate replay's returns. Pin `M_trials`, head hash, and whole-file SHA-256 in the signed approval. Keep within the current 8 MiB per-artifact admission limit. Oversize is a visible refusal. Splitting a searched family would change the trial denominator.
- Retain negative results with their actual returns. A fully observed no-trade window gives a real zero. An abstention can use an all-zero series only with an auditable, predetermined no-entry policy and a fully observed panel. A data failure or a trial with undefined policy leaves the series unavailable. Persist and hash its terminal row and mark the run `REJECT_INCOMPLETE_LEDGER` for admission. Never drop the row or substitute a return.

### Compatibility and statistical closure

Use `promotion.canonical_trial_statistics` at report and admission so both recompute DSR, BH FDR and PBO from the same complete inventory at full precision. Keep the present candidate thresholds. On `746cf42`, canonical statistics require every row to have estimable return moments, so a verified all-zero abstention also blocks admission under v1. The exporter must still write that row and report its exact reason. An all-estimable v1 family can use the existing signing and admission path immediately. The precommitted window policy must yield an exact shared grid. Any divergence from the bound candidate return series blocks admission even if intersecting windows would leave enough sample.

When a complete family has verified all-zero abstentions, add a separately preregistered, versioned extension before using it for promotion:

1. Accept zero rows only with the declared abstention disposition and signed evidence of fully observed no-entry on every window. Keep these rows in the aligned matrix and `M_trials`. Leave missing or degenerate nonzero returns unresolved.
2. Apply BH at q = 0.05 over the full inventory with p = 1 for verified abstentions. Expose their candidate DSR and HAC as unmeasured and their promotion as ineligible. Run the existing 16-partition PBO over all columns, with zero no-trade Sharpe, deterministic plan-order selection on in-sample ties and average out-of-sample rank on ties. Require at least two estimable trials for the variance estimate.
3. Compute the DSR expected-max benchmark using total `M_trials` and the greater of estimable-trial sample Sharpe variance and `1/(T-1)`. Keep the same computation in report and admission. Wire a shared versioned routine around the existing statistics without changing already bound v1 results. Preregister and validate the extension on held-out null fixtures with mixed abstentions before opening any live holdout that uses it.

## 4. Implementation and acceptance

1. Land the plan reader, resumable ledger writer, sealed replay adapter and v1 exporter with synthetic fixtures. Keep the new entry point additive. If the scenario simulator needs engine instrumentation, preserve the bound evaluator and prove canonical replay parity before wiring it to an admission release.
2. Test a three-level book with partial depth and a fee rounding boundary, an aggressive exit, a delayed maker cancel, stale/future books, and a second sweep against consumed depth. Require exact nine-cell output, a full-fill denominator, and invariant base replay p-value and returns.
3. Test pass, measured failure, abstention and error rows, interrupt before and after fsync, retry, reorder, truncate, tamper, duplicate and mismatched plan/window inventory. Verify exact count, chain and refusal of an unestimable family. Compare promotion and admission statistics on an all-estimable fixture. For the versioned extension, add zero-row and mixed-null sensitivity tests before use.
4. Use a synthetic registered candidate to run export → `doppel-promotion` → bundle → verified Ed25519 signature → `admit_shadow()`. Alter one byte in each signed artifact and verify it fails at the expected gate. Verify a missing cell or losing live-fee capacity rejects, and signed canonical inputs reproduce the same immutable admission receipt. Do the production review against the release used by Opus.
